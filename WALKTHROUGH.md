# Walkthrough: Secure Share with E2E Encryption

Ми успішно реалізували повноцінне наскрізне шифрування (End-to-End Encryption) для нашого сервісу обміну файлами.

## 1. Storage Backend (`storage/`)

Сервер залишається "тупим" сховищем зашифрованих блобів.

- **Upload**: Приймає зашифровані дані (base64) + метадані (ім'я, тип).
- **Download**: Віддає зашифровані дані.
- **Security**: Сервер ніколи не бачить вміст файлу і не отримує ключ шифрування.

## 2. Frontend Security (`frontend/`)

Реалізовано криптографію на клієнті (WebAssembly):

- **Algorithm**: ChaCha20-Poly1305 (сучасний, швидкий, безпечний AEAD шифр).
- **Key Generation**: Для кожного файлу генерується унікальний 256-бітний ключ.
- **Encryption**: Файл шифрується в пам'яті браузера перед відправкою.
- **Decryption**: Файл розшифровується в пам'яті браузера після скачування.

## 3. User Flow

1.  **Sender**:
    - Вибирає файл.
    - Браузер генерує ключ і шифрує файл.
    - Зашифрований файл летить на сервер.
    - Користувач отримує посилання: `http://localhost:8080/?id=UUID&key=SECRET_KEY`.
    - Посилання формується динамічно на основі поточного домену.

2.  **Receiver**:
    - Відкриває посилання.
    - Додаток автоматично розпізнає параметри `id` та `key` і переходить в режим **Receiver**.
    - Поля ID та Key заповнюються автоматично.
    - Натискає "Download & Decrypt".
    - Файл скачується, розшифровується і зберігається.

## 4. Dependencies

- `chacha20poly1305`: Шифрування.
- `rand`: Генерація ключів.
- `base64`: Кодування для передачі.
- `urlencoding`: Кодування ключа в URL.

## Як запустити

1. **Backend**:
   ```bash
   cd storage
   cargo shuttle run
   ```

2. **Frontend**:
   ```bash
   cd frontend
   trunk serve
   ```

3. Відкрити `http://localhost:8080`.
